When it helps

    

      
Before you change something
Ask what breaks? Everything that depends on it, hop by hop, in any language. pulse_radius

      
Reviewing a pull request
Ask what did this touch? Each function the diff added, changed, or deleted, and who uses it. pulse_delta

      
Your first hour in a repo
Ask where does it start? The entry points and the code most things depend on, in two calls. pulse_handlers pulse_map

      
Looking for something
Ask where does X live? By name, by typo, or by words in a docstring. pulse_locate

    

    
When it can't see something (code reached only through dynamic dispatch, or names built from strings), it says so instead of guessing.

  






  

    
How it's tested

    
Three kinds of check, all in the repo, all runnable without an API key.

    

      
Against real bugs
500 real bug reports from SWE-bench Verified. Given only the issue text, does the map point at the files the fix changed?

      
Against every language
Each language ships with a small proof repo and the edges it must produce. If a language can't prove its edges, the test suite fails.

      
Against its own docs
Every answer shown for the example repo is checked by a test, so the docs can't drift from the product.

Get started

    
Two commands, once per machine. Needs Python 3.11+ and uv, on macOS or Linux.

    
uv tool install git+https://github.com/sumitrj/CodePulse
codepulse install          # the map in every Claude Code session

    
    
      
  • Then just ask. Start Claude Code in any repo, and the first question builds its map.
    • 
      
  • See it yourself: codepulse . opens the panel for the repo you're in.
    • 
      
  • Stays local. Every tool only reads, and the map lives on your machine.
